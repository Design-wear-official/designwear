# 16 · Design Studio — Build Roadmap

> **Status:** planning document (no code changed yet). This is the build/
> improvement roadmap for the Design Studio. For how the studio works *today*,
> see [10 · Design Studio](10-design-studio.md).

## Context

The Design Studio is feature-rich and usable, but research into the current
implementation revealed it is **lossy at the edges**: the AI-generated graphic
isn't persisted, **Publish sends only the base color + one text string** (the
actual layered design never reaches the backend), editing is drag-only, shapes
are unimplemented, and only the T-shirt renders. This roadmap defines a target
architecture and a phased plan to turn the studio into a complete, lossless,
direct-manipulation editor. Priorities span four areas: **Canvas editing UX**,
**Fidelity & persistence**, **Garment coverage**, and **AI design quality**.

## Current-state assessment

**Architecture (works today):** [`DesignStudioScreen`](../lib/screens/design_studio_screen.dart)
orchestrates a [`CustomDesign`](../lib/models/custom_design.dart) model, renders
via [`DesignCanvas`](../lib/screens/design_studio/design_canvas.dart), with a
5-tool side panel (layers / color / text / emoji / place), undo/redo
([`DesignHistoryService`](../lib/services/design_history_service.dart)), local
save + auto-save ([`DesignStorageService`](../lib/services/design_storage_service.dart)),
Sanity-backed templates ([`DesignTemplateService`](../lib/services/design_template_service.dart)),
and an AI assistant ([`AIAgentService`](../lib/services/ai_agent_service.dart) +
[`AgentChatWidget`](../lib/presentation/widgets/agent_chat_widget.dart)).
Responsive: 3-pane on desktop/tablet, stacked on mobile.

## Target architecture

1. **Unified layer model.** Treat *everything* on the garment as a
   `DesignElement` in one ordered `elements` list — text, sticker, **shape**,
   and **image** (AI-generated or uploaded). Add `DesignElementType.image` and
   retire the special-cased `designImageBase64` overlay (G6) and the legacy
   single text/sticker fields (keep `fromJson` back-compat).
2. **Transformable elements.** Extend `DesignElement` with `rotation`,
   `width`/`height` (images/shapes), and `opacity`; z-order = list order.
3. **Garment registry.** A declarative `Garment` descriptor (id, label,
   front/back asset, print-area rect, collar/pocket anchors) replaces the ad-hoc
   `_garmentAssets` map and hardcoded painter constants — adding a garment
   becomes data, not code.
4. **Per-side design.** Each element carries `side: front|back`; the canvas
   renders the active side; persisted.
5. **Lossless persist + publish.** `toJson` includes all layers (incl. images);
   save captures a thumbnail; Publish sends the full design JSON + preview image
   to the backend and stores it on the Sanity `product`.
6. **Coordinate space.** One canvas-local coordinate system + a print-area rect
   per garment; clamp/snap against it.

## Phased roadmap

### Phase 0 — Data-model foundations *(keystone; unblocks all others)*
- Add `DesignElementType.image`; add `rotation`, `width`, `height`, `opacity`,
  `side` to `DesignElement`; include them in `copyWith`/`toJson`/`fromJson`.
- Persist images as a layer; migrate `designImageBase64` → an `image` element on
  load (back-compat in `fromJson`).
- Define `PrintArea` / canvas coordinate constants.
- **Files:** [`custom_design.dart`](../lib/models/custom_design.dart),
  [`system_prompt.txt`](../assets/system_prompt.txt) (teach the AI the
  `image`/`shape` types, `side`, and transform fields).
- **Acceptance:** a design with text + sticker + shape + image round-trips
  through `toJson`/`fromJson` with positions, rotation, and image intact.

### Phase 1 — Canvas editing UX *(G3, G4, G5)*
- Replace `DraggableElementWidget` with a `TransformableElementWidget`: selection
  box with **resize corner** + **rotate handle**, plus **pinch-to-scale/rotate**
  for touch; live drag with bounds **clamping** to the print area and optional
  **center/edge snapping** with guide lines.
- Implement **shape** rendering in `DesignElementWidget` (rect, circle, line,
  triangle via `CustomPainter`); add a Shapes source/tab.
- Tap empty canvas to deselect; floating **delete/duplicate** on selection;
  *(stretch)* multi-select.
- **Files:** `design_canvas.dart`, new `widgets/transformable_element_widget.dart`,
  `widgets/design_element_widget.dart`, `design_studio_screen.dart` (wire
  size/rotation into `_updateDesign`), `design_studio_constants.dart`.
- **Acceptance:** an element can be moved, resized, and rotated directly on the
  canvas, stays within the print area, and the change is undoable.

### Phase 2 — Fidelity & persistence *(G1, G2, G9, G10, G11)*
- Capture a **thumbnail** (RepaintBoundary → PNG, reuse the `_navigateToTryOn`
  capture pattern) on Save and Publish; store `thumbnailPath`.
- **Lossless Publish:** extend `ApiService.publishRemix` + backend
  [`publish-remix/route.ts`](../designwear-backend/app/api/publish-remix/route.ts)
  + Sanity [`product`](../designwear-backend/sanity/schemaTypes/product.ts) schema
  with `designJson` (full `CustomDesign`) and `previewImage` (uploaded asset);
  render the saved design on product cards/detail.
- Fix provenance chip to use `widget.remixSource` (G10).
- Replace the forced AI auto-generate on open with a **starter-design picker**
  (`getStarterDesigns()`) + an explicit "✨ Generate with AI" action — also
  removes an automatic paid API call on every open (G9).
- **Files:** `custom_design.dart`, `design_storage_service.dart`,
  `widgets/save_design_dialog.dart`, `api_service.dart`, backend
  `publish-remix/route.ts`, Sanity `product.ts`, `design_studio_screen.dart`,
  `design_canvas.dart`.
- **Acceptance:** Save → reopen restores the *exact* design incl. AI image;
  Publish produces a Sanity product whose stored design matches the canvas and
  renders as a thumbnail in the feed.

### Phase 3 — Garment coverage *(G7, G8, G12)*
- Introduce `lib/screens/design_studio/garment_registry.dart`: `Garment`
  descriptors with front/back assets, print-area rect, and collar/pocket anchors.
- Add hoodie/polo/cap/tote artwork (front + back) under `assets/images/`; derive
  `_GarmentOverlayPainter` geometry from the registry instead of constants.
- Render **front/back** from per-element `side`; map Sanity category ids →
  garment ids.
- **Files:** new `garment_registry.dart`, `design_canvas.dart`,
  `custom_design.dart` (uses `side`), `pubspec.yaml` (assets), `assets/images/`.
- **Acceptance:** each garment renders its artwork with the correct print area;
  designing on Back persists and shows independently of Front.

### Phase 4 — AI design quality *(G6, G9; rides on Phase 0)*
- AI/uploaded images become **editable `image` layers** (move/resize/rotate)
  rather than a fixed overlay.
- Keep `system_prompt.txt` in sync with the model (image/shape/side/transform);
  ensure `AIAgentService` round-trips image layers.
- Auto-start: starter picker + on-demand generation (from Phase 2).
- *(Stretch)* print-area auto-fit / background handling for uploaded images.
- **Files:** `ai_agent_service.dart`, `system_prompt.txt`, `design_canvas.dart`,
  `agent_chat_widget.dart`.
- **Acceptance:** "make a sunrise tee" produces a design whose AI image is a
  movable/resizable layer that persists and publishes.

## Sequencing, effort & risk

- **Order:** Phase 0 → (Phase 1 ∥ Phase 2) → Phase 3 → Phase 4. Phase 0 is the
  keystone; 1 and 2 can proceed in parallel after it.
- **Rough effort:** P0 = S, P1 = L, P2 = M (incl. backend), P3 = M (mostly assets
  + geometry), P4 = M.
- **Risks:**
  - **(a)** The P2 backend + Sanity schema change needs a deploy — the only
    cross-repo change.
  - **(b)** Per-garment overlay/print-area geometry is fiddly — mitigate with the
    registry + a temporary calibration overlay.
  - **(c)** `fromJson` back-compat must be preserved for existing saved designs.
  - **(d)** Keep web-safe (guard `dart:io`) and keep the canvas in a
    `RepaintBoundary` for capture.
