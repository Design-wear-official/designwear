# Closing the gaps in DesignWear's T-shirt studio

**No, the studio does not cover all the areas you listed, but it covers more than the four competitors do where it counts.** Of the nine areas, fabric colour, collar, pockets (left and right) and sleeve prints are present in the code. Buttons are drawn but cannot be coloured. Cuffs have a style and a colour but render only on the front view. Hem, neck label, back yoke and side seams do not exist in the studio at all. The competitor evidence matters here: no researched tool documents hem, side-seam or back-yoke printing, and none lets a customer recolour collar, cuffs or buttons. So hem, side seams and button colour are not industry-standard gaps. The real market-standard gaps are the **inside and outside neck label** and the **back neck (nape) and upper back** zones. The larger risk is quality, not coverage. The new pocket, sleeve and per-area colour work is uncommitted, and the audit found that the new garment images are JPEGs with a baked-in checkerboard background. It also found that overlay coordinates were calibrated for the old photo, that previews and print sheets drop sleeve and pocket art, and that the AI assistant likely resets the new options. Fixing those should come before adding new areas. Caveats: the code findings come from reading source, and nothing was run or rendered. Several competitor facts come from search summaries because the Printful, Spreadshirt and Printify help pages returned HTTP 403. Spreadshirt and Custom Ink print-area sizes were not found.

## The nine areas: what the code supports today

The model exposes exactly **four colour channels**: body colour (`baseColor`), plus collar, pocket and cuff colours that each default to a shared `trimColor` (`lib/models/custom_design.dart:165-189`). There is no sleeve, button, hem, label or placket colour field anywhere in `lib/`. Print areas are the `DesignSide` enum with **six sides**: front, back, left sleeve, right sleeve, left pocket and right pocket (`custom_design.dart:19-33`).

| Area | Supported in code | Verdict |
|---|---|---|
| Fabric colour | 40 swatches, custom hex, recents, palettes (`color_panel.dart:35-83, 196-327`); finish solid/heather/vintage is a texture on the front only | Covered |
| Collar | Style crew/vneck/polo plus colour (8 swatches only, no hex picker); front view only | Partial |
| Buttons | Two polo buttons drawn with a shade derived from the collar colour (`design_canvas_painters.dart:189-196`); no model field, no UI | Not colourable |
| Pockets, left and right | Style none/left/right/both, pocket colour, and a dedicated print view per pocket | Covered, with defects |
| Sleeves | Left and right sleeve print sides; sleeve colour is just the body colour | Print yes, colour no |
| Cuffs | Style none/banded/rolled and cuff colour, drawn on the front overlay only; sleeve views ignore them | Partial |
| Hem | Only a fixed 10% black decoration band on the sleeve painter | Absent |
| Neck label | Backend defines a `neck_label` placement (`designwear-backend/src/garments.js:17-24`) but maps it to no app side | Backend only, unreachable |
| Back yoke / nape | No enum value, no UI; the back view has no overlay at all | Absent |
| Side seams | No enum value, no UI | Absent |

Three design choices explain the partial rows. The garment overlay (collar, pockets, cuffs, finish) is gated to the front view only (`design_canvas.dart:221-223`), so the back, the sleeves and the pocket close-up never receive collar, cuff or finish rendering. The "Left chest" control in the Placement panel is cosmetic: it sets `printLocation`, whose only reader is a label in the Layers list (`placement_panel.dart:35-49`, `layers_panel.dart:125`), so real left-chest printing is the left-pocket side. Finally, the studio is effectively T-shirt only. Hoodie, polo, cap and tote exist in the registry with no images (`garment_registry.dart:100-103`), the UI selector lists only T-Shirt, and `GarmentRegistry.updateFromBackend` has no callers, so backend garment data never reaches the studio. The "polo" collar is a T-shirt collar variant, not the polo garment.

## Where the competitors set the bar

The industry-standard placement set is **left chest, centre chest, full front, back, both sleeves, inside neck label and outside neck label**, with pocket treated as a sub-case of left chest. Printful lists left chest print at 2.5x2.5 to 5x5 in, centre chest 6x6 to 10x8 in, full front 12x16 in (15x18 in on select DTG products), back 10x12 to 12x16 in, sleeve usually 4x3.5 in, and an inside label of usually 3x3 in. It also sells an outside label of 3x3 in and custom inside labels at $0.99 each ([Printful placement guide](https://www.printful.com/blog/t-shirt-design-placement-guide), [Printful inside labels](https://www.printful.com/ca/custom-inside-labels)). Printify, which shares blanks with Printful, matches these sizes and adds a back collar zone of 1-3 in, an upper back of 10-14 x 1-6 in, a pocket of 2.5-4 in and an inner neck label of 2.5x2.5 in. It also lets users add an inner or outer neck label and a sleeve print when designing a tee ([Printify placement guide](https://printify.com/blog/t-shirt-design-placement-guide/), [Printify custom neck label help](https://help.printify.com/hc/en-us/articles/9691640023185-How-can-I-create-a-custom-neck-label)). Printify also stocks a dedicated pocket tee ([Printify pocket tee](https://printify.com/app/products/1358/bella-canvas/unisex-pocket-t-shirt)). Custom Ink offers Front/Back toggles and a "Sleeve Print" control for special areas, with availability varying by style ([Custom Ink lab help](https://www.customink.com/help_center/navigate-the-lab)). Spreadshirt's official help gives only a generic print-area concept, with no per-placement sizes found ([Spreadshirt help](https://help.spreadshirt.com/hc/en-gb/articles/360000052513-Help-with-the-Customize-Tool)). Print-shop sources add a nape zone (2.5x2.5 in, 1-2 in below the rear collar seam) and an upper-back zone (12x4 in) ([ScreenPrinting.com](https://www.screenprinting.com/blogs/news/t-shirt-design-placement-guide-your-easy-reference-for-industry-standard-layouts)). That makes back neck and upper back a realistic target for the "back yoke" request.

Against that standard, DesignWear leads on pockets, where it has two dedicated print views, and on per-part colour. It trails on labels and the back neck. Hem, side seam and back-yoke printing appear in none of the Printful or Printify guides, so these should be treated as optional extras. Per-part recolouring is a differentiator rather than a gap: Custom Ink exposes only a single "Product Colors" control, Printify's polo has collar, cuffs and buttons fixed by the blank, and Printful's polo page mentions only garment and thread colours ([Printify embroidery polo](https://printify.com/app/products/1730/port-authority/unisex-polo-shirt-embroidery), [Printful custom polos](https://www.printful.com/uk/custom-polo-shirts)). Contrast looks are sold as separate colourways such as Bonfire's 3/4-sleeve baseball tee ([Bonfire baseball tee](https://bonfire.com/catalog/3-4-sleeve-baseball-t-shirt)). That evidence is absence-based, since no source states outright that these tools lack per-part colour. Polo button colour exists in manufacturer catalogues as a dyed-to-match or contrast attribute, which suggests it is a made-to-order feature, not a decorator one ([Corporate Casuals](https://www.corporatecasuals.com/embroidered/polo-shirts/page13), via search summary).

## Quality defects that undercut the existing coverage

The areas that exist are weaker than the feature list implies. The four new `*_cutout.png` assets are **1024x1024 JPEGs with a baked grey-and-white checkerboard**, not transparent cutouts, and the canvas tints them with the garment colour (`design_canvas.dart:138-141, 177-181`). The left and right sleeve files are byte-identical (md5 09d82cfd...), while the canvas also mirrors the right view, so a genuine right-sleeve image supplied later would be flipped twice. Overlay coordinates are stale: the painters were calibrated for the old 1080x1440 `tshirt_white.png` (`design_canvas_painters.dart:83`), and the new image is square. By computation from the constants, pockets overhang the armhole by about 50 image pixels, the V-neck tip lands near y=247 against a photo neckline near y=160, and the fabric-finish clip spills past the hem. No render was done, so a visual check is the first verification step.

Data integrity downstream is the second weak point. The design JSON survives save, publish, remix and order storage, but every other consumer drops sleeve and pocket content. Publish captures only front and back canvases (`design_studio_screen_actions.dart:385-386`), and the backend schema holds only `previewImage` and `backPreviewImage`. The offstage captures are probably blank, because `Offstage` does not paint (unverified at runtime). The fulfilment print sheet lists elements as type, content, font and colour with no side, no collar, pocket or cuff choices and no trim colours (`designwear-backend/src/print.js:35-69`), so a print operator cannot tell which sleeve or pocket an element belongs to. The AI assistant is a third leak: its prompt documents neither `side` nor the garment options and tells the model that unlisted elements are removed (`design_prompt.txt:63`). The app then replaces the whole design with the reply, so omitted keys fall back to defaults (`custom_design.dart:350-357`). Pocket artwork cannot be generated, because the backend accepts only front, back, left and right. The pricing code also ignores every option, with no surcharge for sleeve or pocket prints, whereas Printful charges separately for labels.

Smaller defects compound this. Layer reorder indexes the per-side list but applies it to the full cross-side list (`design_studio_screen_layout.dart:585-588`, `custom_design.dart:392-397`). Drag clamps are the front-area bounds on every side, and the "8 x 8 cm" pocket label is not enforced. The pocket close-up renders a patch even when pocket style is none. An existing widget test (`test/screens_test.dart:225-265`) now expects a `SleevePainter` that the photo branch bypasses; this is inferred and the tests were not run. The 3D preview button is a stub, and the only new test file covers the model alone.

## What to fix and build next, in priority order

First, repair the foundations: **replace the four JPEG assets with real transparent PNG cutouts**, supply a true right-sleeve image or drop the redundant flip, and **recalibrate overlay coordinates** to the new square asset, ideally as fractions of the image rather than pixels. Everything else renders on top of these, and no feature should ship on a misaligned base. Second, make the existing data reach fulfilment: composite or capture sleeve and pocket sides into previews, add side and option lines to the print sheet, and fix the layer-reorder indexing. A design the factory cannot read is a liability for every area added afterwards. Third, make the AI assistant side- and option-aware by instructing it to echo `collarStyle`, `pocketStyle`, trim colours and `side`, and by merging replies into the current design instead of replacing it.

Fourth, add the market-standard missing areas. The **inside and outside neck label** is the top choice: Printful and Printify both sell it, Printify says the label is its smallest area at 2.5x2.5 in, the backend already defines a `neck_label` placement, and it needs only a new `DesignSide` value, a small canvas view and a pricing line. A **back neck and upper back** zone comes next. This is your "back yoke", sized by the 2.5x2.5 in nape and 12x4 in upper-back figures above, and it needs a back-view overlay. Fifth, close the colour gaps that cost little: a `buttonColor` field with a chip in `color_panel.dart:568-573` and a painter parameter, a hex picker for trim colours (only the body has one today), and sleeve-hem and cuff rendering on the sleeve views. These are differentiators, not parity items, so they rank below the neck label.

Last come the optional items. Hem print and side-seam prints have no dimensioned specification in any source and no competitor documentation, so build them only if there is customer demand. Reconcile the print-size labels with the backend (the sleeve is "8 x 10 cm" in the app against 1200x1200 px at 300 dpi, about 10.2 cm square, in the backend), enforce area clamps per side, and add a pocket placement to the backend. Wire up the garment registry or hide the options panel on garments without an overlay, and delete the dead Placement tool, `bare` flag and unused tab widgets. Add painter and widget tests for pockets, colour chips and the side-preserving flows.

## Conclusion

The competitor research reframes the question. "All areas" is a moving target, because the four tools converge on a short list (chest, front, back, sleeves, labels), and DesignWear already exceeds them on pocket views and per-part colour. The honest gap is therefore narrow: neck labels and a back-neck zone, not hem, side seams or button colour. The larger finding is that DesignWear's coverage is shallower than its surface suggests. Most options render only on the front view and survive only as raw JSON, so a customer can design a sleeve or pocket print that never reaches a preview or the factory. The cheapest credibility gain comes from making the existing six sides and four colour channels work end to end before widening the list.

Remaining uncertainties are unresolved here. Whether the Gemini model echoes the new option keys, whether offstage capture works on a real device, and how the overlays actually look on the new assets are all unverified. Spreadshirt and Custom Ink sizes, and which polo parts are customer-selectable versus manufacturer-only, were not found. Hem, right-chest and polo-placket dimensions rest on vendor-specific sources and search summaries.
